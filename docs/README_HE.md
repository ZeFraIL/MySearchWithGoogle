🎯 מטרת הפרויקט
•	**איזו בעיה האפליקציה פותרת:** מאפשרת למשתמש לבצע חיפושים בגוגל ישירות דרך WebView מובנה ולהחזיר את כתובת ה-URL של הדף שנבחר לחלון הראשי של האפליקציה.
•	**מדוע משימה זו חשובה:** היא מדגימה אינטראקציה בין אקטיביטיז באמצעות `ActivityResultLauncher`, עבודה עם `WebView` והעברת נתונים דרך `Intent`.
•	**קהל יעד:** מפתחים הלומדים את יסודות הפיתוח לאנדרואיד.

**דרישות פונקציונליות**

•	הצגת תוצאות חיפוש גוגל בתוך האפליקציה.
•	אפשרות לחזור למסך הראשי עם כתובת ה-URL של הדף הנוכחי.
**דרישות לא פונקציונליות**

•	**אמינות:** פעולה יציבה במהלך המעבר בין החלונות.
________________________________________
🧠 ארכיטקטורה כללית
•	**הגישה שנבחרה:** MVC (Model-View-Controller)
•	**מדוע נבחרה גישה זו:** הפרויקט הוא בקנה מידה קטן, לכן מבנה ה-Activity הסטנדרטי של אנדרואיד עונה באופן מלא על הצרכים ללא סיבוך מיותר.
•	**מרכיבי המערכת העיקריים:**
    - `MainActivity`: מציג את התוצאה ומפעיל את החיפוש.
    - `Search`: מעבד את הקלט ומציג את ה-WebView.

🧩 תיאור מפורט של המחלקות
📌 מחלקה: MainActivity
**תפקיד:** נקודת הכניסה לאפליקציה.
**אחריות:** הצגת הקישור שהתקבל ממנוע החיפוש.
**שיטות עיקריות:** 
- `onCreate()` — הגדרת פריסה (layout) ומאזינים (listeners).
- `initComponents()` — אתחול ממשק המשתמש ו-`ActivityResultLauncher`.
**אינטראקציה עם מחלקות אחרות:** מפעילה את `Search` דרך `Intent`.
________________________________________
📌 מחלקה: Search
**תפקיד:** מסך החיפוש.
**אחריות:** הזנת שאילתה, הצגת WebView, החזרת קישור.
**שיטות עיקריות:**
- `initElements()` — אתחול רכיבים.
- `backWithLink()` — מחזירה את ה-URL הנוכחי ל-`MainActivity`.
- `myWebViewClient` — מחלקה פנימית לניהול טעינת דפים בתוך ה-WebView.
________________________________________
🔄 תיאור זרימת העבודה (Workflow)
**תרחיש:**
1. המשתמש לוחץ על "Start Search" ב-`MainActivity`.
2. מזין טקסט ב-`Search` ולוחץ על כפתור החיפוש.
3. גולש בתוצאות ב-`WebView`.
4. לוחץ על כפתור החזרה, וכתובת ה-URL של הדף מוצגת ב-`MainActivity`.
